# 한국어 세로 쇼츠 모션그래픽

나레이션 음원 하나를 넣으면 **자막·장면 구성·모션·렌더까지 끝난 MP4** 가 나온다.
화면의 모든 것을 HTML/SVG 로 직접 그리는 것이 기본이다.
**실사 클립이 있으면 원하는 장면에만 깔고 그 위에 도식을 얹을 수 있다** — 「실사 클립을 섞을 때」 참조.

---

## 먼저 읽을 것 — 핵심 3원칙

절차를 다 지켜도 이 셋이 무너지면 결과가 무너진다. **판단이 갈릴 때는 여기로 돌아온다.**

### 1. 고정하는 것은 셋뿐이다

```
상단 안전선  y ≥ 120        하단 안전선  y ≤ 1600        자막 기준선  y = 1560
```

그 사이 **1480px 는 매 장면 새로 짠다.** 형태·무게중심·캐릭터 포즈를 앞 장면과 다르게 한다.

> **왜:** 자막이 매 장면 자리를 옮기면 눈이 따라가느라 내용을 못 읽는다.
> 반대로 **자막 말고 전부 고정하면 슬라이드쇼가 된다.** 고정과 자유의 경계가 정확히 이 셋이다.
> *실제로 7장면짜리 두 편에서 같은 형태가 하나도 나오지 않았다 — 가로 바 / 가로 카드 / 원형 게이지 / 세로 알약 / 사선 분할 / 블록 격자 / 원근 통과.*

### 2. 캐릭터는 제3의 층이다

무대(어두운 중성) · 주석(빨강·노랑·녹색) · **캐릭터(살구+파랑+갈색)** — 셋이 서로 다른 팔레트를 가진다.
캐릭터는 `#E12F2C` 를 입지 않는다.

> **왜:** 같은 색이면 같은 층으로 읽힌다. 회색 픽토그램은 화살표·아이콘과 같은 급으로 보인다.
> 층이 갈려야 **"사람이 도식 앞에 서 있다"** 가 된다.

### 3. 캐릭터의 동작 벡터가 정보를 겨눈다

캐릭터를 **도식의 대각 반대편**에 둔다. 지목하는 팔·뻗은 손이 실제로 정보를 향해야 한다.

> **왜:** 정보 옆에 캐릭터를 세우는 것만으로는 "함께 있는" 것이지 **"맞물린"** 것이 아니다.
> *인물을 도식 오른쪽 아래에 뒀더니 지목하는 팔이 화면 밖 허공을 가리켰다. 대각 반대편으로 옮기자 그제야 맞물렸다.*

## 먼저 읽을 것 — 재사용 기준

지난 영상의 것을 **무조건 다시 쓰지도, 무조건 버리지도 않는다.** 3층으로 나눠 판단한다.

| 층 | 무엇 | 판단 |
|---|---|---|
| **1층** | 팔레트 · 타이포 · 안전선 · 이징 · 하드컷 문법 · 캐릭터 생성기 | **항상 그대로.** 이게 "같은 채널로 보이는" 것의 정체다 |
| **2층** | 그래픽 자산(관공서·폰·달력·차트 틀) · 구도 · 효과 28종 | **아래 시험 셋을 다 통과하면 재사용** |
| **3층** | 장면 배치 · 타임라인 · 무게중심 | **매번 새로.** 여기를 굳히면 슬라이드쇼가 된다 |

**2층 재사용 시험 — 셋 다 통과해야 쓴다**

1. 대본 문장이 그 효과의 **발동조건에 실제로 걸리는가?** ("지난번에 예뻤으니까"는 이유가 아니다)
2. **바로 앞 장면과 형태가 다른가?**
3. 캐릭터라면 **포즈가 앞 장면과 다른가?**

> **재사용의 적은 "영상 간 반복"이 아니라 "인접 장면의 반복"이다.**
> 폰 목업은 두 편에 모두 나왔지만 문제없었다 — 둘 다 "앱으로 신청·확인"이 대본에 있었다.
> 문제는 **한 영상 안에서** 만세 포즈를 연달아 썼을 때 컷이 안 느껴진 것이었다.

**재사용하면 안 되는 신호**

- 대본에 없는 소품을 "화면이 비어서" 넣고 싶어질 때 → **비워 둔다.** 무대가 프레임을 채우고 있다
- 지난 영상의 장면 순서를 그대로 따라가고 싶어질 때 → **대본이 다르면 장면 수도 다르다**

## 준비물

| 도구 | 확인 | 없으면 |
|---|---|---|
| Node.js 18+ | `node -v` | nodejs.org |
| Python 3.8+ | `python -V` | python.org |
| ffmpeg · ffprobe | `ffmpeg -version` | ffmpeg.org (PATH 등록 필요) |
| HyperFrames CLI | 자동 (`npx hyperframes@0.8.14`) | 첫 실행 때 받는다 |
| Noto Sans KR | Medium · Bold · Black **.otf** | fonts.google.com/noto/specimen/Noto+Sans+KR |

**폰트를 먼저 준비한다.** `.ttf` 가 아니라 **`.otf`** 여야 하고, 파일명은 `NotoSansKR-Medium.otf` / `-Bold.otf` / `-Black.otf` 로 맞춘다.
`@font-face` 없는 폰트를 CSS 에 쓰면 `check` 가 `font_family_without_font_face` 로 막는다. **대체 폰트(fallback)에도 `@font-face` 가 필요하다** — 없으면 fallback 을 아예 적지 않는다.

```bash
# 준비 확인 (한 번만)
node -v && python -V && ffmpeg -version | head -1
ls "[스킬 폴더]/assets"        # build.py chargen.py hyperframes.json scene-template.html
```

### 스킬에 들어 있는 것

```
[스킬 폴더]/
  SKILL.md                       이 문서
  reference/STYLE-RULES.md       효과 28종 + 발동조건표 + 실측 팔레트/이징  ← 6단계에서 반드시 연다
  assets/scene-template.html     장면 뼈대 (무대·리본·출처·자막·안전선)
  assets/chargen.py              3D 클레이 캐릭터 생성기 (4포즈)
  assets/build.py                템플릿 → index.html 빌드 + id 중복 검사
  assets/hyperframes.json        프로젝트 설정
```

## 뭘 넣으면 뭐가 나오나

**입력** — 한국어 나레이션 `mp3`/`wav` 1개. 그게 전부다. 대본 텍스트는 있으면 좋지만 없어도 전사한다.
실사 클립은 **선택**이다. 있으면 원하는 장면에만 깐다.

**트리거**
```
[음원 경로]
영상 만들어줘
```

**출력**
- `[작업 폴더]/[주제]/[주제]_NN초.mp4` — 1080×1920 · 30fps · 나레이션 포함
- `[작업 폴더]/[주제]/_gen/s1.html …` — 장면별 소스 (한 장면만 고쳐 다시 렌더할 수 있다)
- `[작업 폴더]/[주제]/out/s1.mp4 …` — 장면별 렌더

**소요** — 45~60초 영상 기준 장면 7개 안팎, 렌더는 장면당 15~20초.

## 작업 순서

**순서를 바꾸지 않는다.** 특히 6단계(효과 선택)를 건너뛰고 7단계(레이아웃)로 가면 "예뻐 보여서" 고른 효과가 들어간다.

### 0. 재료 확인 — 없으면 여기서 멈춘다

| 있어야 하는 것 | 없으면 |
|---|---|
| 나레이션 음원 | **멈추고 요청한다.** 이게 없으면 아무것도 못 한다 |
| 폰트 3종 `.otf` | **멈추고 요청한다.** 렌더가 통째로 실패한다 |
| 출처 표기에 쓸 기관·연도 | **묻는다.** 모르면 지어내지 않는다 |
| 고유명사(기관명·서비스명·제도명) | 전사가 흐리면 **사용자에게 확인받는다** — 화면에 글자로 나간다 |

> 재료가 다 차지 않은 채로 **최종 렌더까지 가지 않는다.** 중간까지 만들고 무엇이 왜 필요한지 말한다.

### 1. 전사

```bash
mkdir -p "[작업 폴더]/[주제]"/{_gen,audio,fonts,out}
cp "[스킬 폴더]/assets/build.py"    "[작업 폴더]/[주제]/"        # 루트에 둔다
cp "[스킬 폴더]/assets/chargen.py" "[작업 폴더]/[주제]/_gen/"   # _gen 에 둔다
cp "[스킬 폴더]/assets/hyperframes.json" "[작업 폴더]/[주제]/"
cp "[폰트 폴더]/"*.otf "[작업 폴더]/[주제]/fonts/"
cp "[음원 경로]" "[작업 폴더]/[주제]/audio/vo.wav"

cd "[작업 폴더]/[주제]"
npx --yes hyperframes@0.8.14 transcribe audio/vo.wav --language ko
```

`audio/transcript.json` 에 단어별 `{text, start, end}` 가 나온다. **초를 프레임으로 바꿔 읽는다** — `round(start * 30)`.

### 2. 자막 분할 — 글자 수가 아니라 호흡

- 단어 사이 **간격이 벌어지는 지점**이 호흡이다. 거기서 끊는다.
- 한 줄은 **880px 안에 들어가야 한다.** 64px 기준 대략 **13~14자**. 넘으면 두 줄.
- 두 줄일 때도 **호흡으로** 나눈다. 글자 수를 맞추려고 어색한 데서 자르지 않는다.
- **연속한 두 자막 사이를 최소 1프레임 비운다.** (안 비우면 경계에서 겹친다)

산출: `| # | 자막 | 시작f | 끝f | 줄 수 |` 표.

### 3. 장면 구성 — 160~290프레임

- 자막을 **의미 단위**로 묶는다.
- 목표 **장면당 160~290프레임.** 설명형 대본의 실측 대역이다.
- 컷은 **말과 말 사이 빈 프레임**에. 간격이 큰 지점(20프레임 이상)이 좋은 컷 자리다.
- 너무 짧은 덩어리(100프레임 미만)는 앞뒤에 붙인다. 한 장면 안에서 **하드 스왑**으로 두 비트를 처리해도 된다.

산출: `| 장면 | 프레임 | 길이 | 자막 | 주제 |` 표. **합계가 음원 총 프레임과 일치**하는지 검산한다.

### 4. 무대와 틴트

| 장면 성격 | 틴트 |
|---|---|
| 중립 · 설명 | `#14181A` |
| 위기 · 손해 · 마감 | `#191416` |
| 혜택 · 증가 · 성공 | `#141A16` |
| 가치 · 자산 | `#1A1814` |

무대는 **틴트 단색 + 그리드(90px, 흰색 4.5%) + 광원 풀 + 그레인 5%.** 이 넷은 매 장면 같다.

### 5. 여기서 사용자에게 중간 보고

2·3단계 표를 보여주고, **고유명사 중 전사가 흐린 것을 확인받는다.** 장면 구성이 틀리면 이후 작업이 통째로 헛돈다.

### 6. 효과 선택 — 이 스킬의 핵심

**`reference/STYLE-RULES.md` 3장의 발동조건표를 연다.** 자막의 **동사와 수치**를 보고 거기 걸리는 효과만 고른다.

#### 이름 붙이기 · 조건 못 박기

| 말이 이런 상태면 | 효과 |
|---|---|
| 무언가에 이름을 붙인다 | **E3** 라벨 플레이트 |
| 조건·기간·분류를 한 단어로 못 박는다 | **E4** 칩 라벨 |
| 작은 부분을 조용히 가리킨다 | **E15** 리더라인 + 소형 라벨 |
| 여러 항목을 차례로 얹는다 | **E16** 순차 등장 (12프레임 스태거) |

#### 수치

| 말이 이런 상태면 | 효과 |
|---|---|
| 수치가 커진다 · 한도가 늘어난다 | **E5** 게이지 채움 (가로 바 / 원형) |
| 숫자를 소리내어 말한다 | **E6** 대형 숫자 슬램 (102.4% → 100%) |
| "A였는데 B가 됐다" | **E7** 고스트 교체 |
| 여러 개가 합쳐져 총량이 된다 | **E8** 블록 스택 |
| 하나가 없어진다 · 못 쓰게 된다 | **E9** 블록 소멸 |
| 수량을 세어 보여준다 | **E18** 픽토그램 격자 |

#### 비교 · 분기

| 말이 이런 상태면 | 효과 |
|---|---|
| 같은 축에서 둘 이상을 비교한다 | **E11** 도트-라인 비교 차트 |
| 둘 중 하나만 · 둘이 갈린다 | **E12** 대비 스플릿 — **9:16 에서는 상하 사선** |
| "안 된다 · 못 한다 · 없어진다" | **E13** X 마크 |

#### 시간 · 마감

| 말이 이런 상태면 | 효과 |
|---|---|
| 시간이 줄어든다 · 기한이 다가온다 | **E10** 스탬프 스태거 |
| 기한이 임박했다 · 시간이 없다 | **E23** 시계 가속 (`power2.in`, 감속 없이 멈춘다) |

#### 사람

| 말이 이런 상태면 | 효과 |
|---|---|
| 사람의 감정·행동을 가리킨다 | **E17** 3D 클레이 캐릭터 (4포즈) |
| 수치가 그 사람에게 일어난 일이다 | **E21** 캐릭터 × 텍스트 — 숫자와 캐릭터를 **같은 래퍼**에 |
| 도식이 누군가에게 좋은/나쁜 소식이다 | **E27** 반응 프레이밍 — **9:16 에서는 Z자 대각** |
| 손으로 조작한다 · 신청한다 · 한 번에 끝난다 | **E22** 스마트폰 탭 리플 (리플은 **버튼 뒤에**) |

#### 공간 · 이동

| 말이 이런 상태면 | 효과 |
|---|---|
| 장소·시점을 콕 집는다 | **E14** 핀 드롭 |
| 어디서 어디로 · 어떤 순서로 진행되는지 | **E24** 경로 드로잉 (30프레임, 강한 감속) |
| 위치·동선 자체가 메시지다 | **E25** 액자 지도 + 카메라 팬 |
| 누가/무엇이 어디에 있는지 | **E26** 유닛 마커 |
| 막혀 있던 것이 열린다 · 선택지가 넓어진다 | **E28** 원근 통과 |

#### 항상 켜 두는 것 — 밀도에서 세지 않는다

| | 효과 |
|---|---|
| 장면의 주제를 못 박는다 | **E19** 리본 태그 (좌상단) |
| 수치의 출처를 밝힌다 | **E20** 출처 표기 (우상단) |
| 무대·자막 자체 | **E1** 무대 선노출 · **E2** 자막 |

**표에 걸리는 말이 없으면 그 장면에는 효과를 넣지 않는다.** 무대와 자막만으로 간다.

**장면당 효과는 최대 3개.** 각 효과의 지속·이징은 규칙서 3장의 값을 그대로 쓴다 (실측값이다).

> **E12 · E27 은 9:16 에서 형태가 바뀐다.** 규칙서의 이름(좌우 스플릿 / 좌우 인물)은 16:9 기준이다.
> 세로에서 좌우 1:1 은 각 면이 540×1920 슬라이버가 되므로 **E12 는 상하 사선**, **E27 은 Z자 대각**으로 바꾼다. 둘 다 렌더로 검증했다.

### 7. 레이아웃 — 매 장면 새로 짠다

고정하는 것은 **셋뿐**이다.

```
상단 안전선   y ≥ 120       이 위는 잘릴 수 있다
하단 안전선   y ≤ 1600      쇼츠 UI 가 덮는다
자막 기준선   y = 1560      한 줄 top:1478 / 두 줄 top:1396 — 둘 다 1560 에서 끝난다
```

그 사이 **1480px 는 매 장면 다시 구성한다.** 아래 시험을 통과할 때까지 다시 짠다.

- [ ] 바로 앞 장면과 **형태**가 다른가? (가로 바 / 세로 스택 / 가로 카드 / 원형 / 격자 / 사선 분할 …)
- [ ] 바로 앞 장면과 **무게중심 사분면**이 다른가? (좌상·우상·좌하·우하·중앙)
- [ ] 캐릭터가 있다면 **포즈**가 앞 장면과 다른가? (rush · point · cheer · grief)
- [ ] **읽어야 하는 것이 2개 이하**인가? (리본·출처는 세지 않는다)
- [ ] 캐릭터의 **동작 벡터가 정보를 겨누는가**?
- [ ] **DOM 층 순서**가 맞는가? — 무대 → 환경/색면 → 도식 → 캐릭터 → 고정 UI → 자막

읽을 것이 3개가 되면 — 하나를 리본으로 올리거나, 사물에 새기거나(디제틱), 시간을 나눠 하드 스왑한다.

**한 장면이 두 비트로 나뉘면 리본도 함께 하드 스왑한다.** 리본은 고정 UI 지만 **장면의 주제를 지는** 자리다.
비트가 바뀌었는데 리본이 앞 주제를 달고 있으면 화면이 어긋난다. 클립 두 개로 나눠 같은 프레임에 교체한다.

## 실사 클립을 섞을 때 — 선택

기본은 전부 그리는 것이다. 그런데 **찍는 쪽이 이기는 장면**이 있다 — 사람의 표정, 실제 장소,
손이 서류를 다루는 순간. 그런 장면만 실사로 깔고 나머지는 그대로 도식으로 간다.

7장면짜리 두 편에서 각각 4장면을 실사로 바꿔 검증했다.

### 어느 장면을 실사로 하나

| 찍는 쪽이 이긴다 | 반드시 도식이어야 한다 |
|---|---|
| 표정 · 반응 (놀란다 · 곤란해한다) | **"~에 없다"** — 없는 것은 못 찍는다 |
| 실제 장소 (세무서 · 법원 · 상담 창구) | 목록 · 순서 (첫째/둘째 · ①②) |
| 손이 사물을 다루는 순간 | 수치의 비교 · 배분 (100 → 150 · 200~600) |
| 분위기 자체가 내용인 장면 | 조건 · 준비물 · 판정 |

**판정 · 조건 · 결론은 실사에 맡기지 않는다.** 화면에 안 찍힌다.
*「압류 전까지는 등기부등본에 안 나온다」를 그리는 방법은 하나뿐이었다 — 있는 항목들을 문서 안에
먼저 보여주고, 체납 세금만 테두리 밖에 두는 것. 이건 카메라로 못 찍는다.*

### 순서 — 장면 구성이 먼저다

1. **전사 · 자막 분할 · 장면 구성까지 먼저 끝낸다.** 장면 경계는 **녹음된 음원의 침묵**에서 나온다.
   대본 텍스트만 보고 정할 수 없다.
2. **장면별 초수 표를 사용자에게 준다.** 그걸 들고 클립을 주문한다.
3. **그동안 전 장면을 도식으로 완성해 둔다.** 클립이 마음에 안 들면 그대로 쓸 수 있어야 한다.
4. 클립이 오면 **해당 장면만** 실사 무대로 다시 짓는다. 도식 장면은 손대지 않는다.

### 주문은 반드시 길게 시킨다

AI 영상은 앞뒤 프레임이 흔들리거나 뭉개져 못 쓴다. **10초 단위로만 나오는 모델이면 전부 10초로 받는다.**
남는 건 자르면 되고, 모자란 건 못 만든다.

> 한 편에서 4개 중 3개가 짧게 와서 `setpts` 로 최대 12% 늦춰 썼다. 느린 팬이라 티는 안 났지만,
> 길게 받은 다음 편에서는 속도를 한 번도 안 건드렸다.

프롬프트에 한 줄 더 넣으면 좋다 — **"핵심 동작이 클립 중간 60% 안에서 끝나게."**
그래야 앞뒤를 마음껏 버릴 수 있다.

### 클립 준비 — 구간을 고르는 것이 편집이다

```bash
# ① 워터마크 위치를 먼저 확인한다. 눈금을 그려 재는 게 확실하다
ffmpeg -i clip.mp4 -vf "scale=324:576,drawgrid=w=324:h=150:color=red@0.9:t=2" -frames:v 1 peek.png

# ② 잘라내기 · 확대 · 워터마크 제거를 한 번에.  -ss 로 쓸 구간의 시작을 고른다
ffmpeg -ss [시작초] -i clip.mp4 -an \
  -vf "scale=1080:1920:flags=lanczos,delogo=x=843:y=1678:w=114:h=124,fps=30,tpad=stop_mode=clone:stop_duration=1" \
  -frames:v [목표프레임] -c:v libx264 -crf 16 -preset medium -pix_fmt yuv420p -r 30 stage/sN.mp4
```

- **시작초는 「핵심 동작이 우리 도식이 터지는 프레임에 오도록」 고른다.** 이게 이 작업의 핵심이다.
  *놀라는 표정이 클립 4.5초에 오고 우리 슬램이 장면 2.8초에 있으면 시작은 1.7초다.*
- `tpad` 를 붙여야 반올림으로 1프레임 모자랄 때 마지막 프레임이 채워진다.
- 클립이 짧으면 `setpts=[배율]*PTS` 를 `scale` 앞에 넣는다. **10% 안쪽이면 티가 안 난다.**

**★ 가장자리의 어두운 띠를 레터박스로 오해하지 말 것.**
어두운 앞바닥 · 그늘진 책상 · 흰 테이블 · 얕은 심도인 경우가 많다. 자르기 전에 사용자에게 확인한다.
*실제로 네 클립을 레터박스로 오판해 크롭할 뻔했다. 전부 진짜 화면 내용이었다.*

### `<video>` 는 `<audio>` 와 같은 1급 미디어다

렌더러가 `querySelectorAll("video[data-start], audio[data-start]")` 로 잡아 **프레임마다 `currentTime` 을
맞춘다.** 결정적으로 렌더된다.

```html
<div id="root" data-composition-id="main" ...>
  <video id="bgv" src="stage/s1.mp4" muted playsinline
         data-start="0" data-duration="4.6667" data-track-index="0"></video>
  <div id="stage" class="clip live" data-start="0" data-duration="4.6667" data-track-index="1">
    <div class="tint"></div><div class="scrT"></div><div class="scrB"></div>
  </div>
  ...
```

**`<video>` 는 root 의 직계로, 그리고 DOM 맨 앞에 둔다.** z 순서는 DOM 순서를 따르므로
뒤에 두면 도식을 통째로 덮는다.

무대 CSS — 이 세 겹이 실사를 우리 화면으로 만든다.

```css
#bgv{position:absolute;left:0;top:0;width:1080px;height:1920px;object-fit:cover;display:block}
#stage.live{background:transparent}
#stage .tint{position:absolute;inset:0;background:rgba(6,9,11,.17)}
#stage .scrT{position:absolute;left:0;top:0;width:1080px;height:420px;
  background:linear-gradient(180deg,rgba(6,9,11,.82) 0%,rgba(6,9,11,.44) 52%,rgba(6,9,11,0) 100%)}
#stage .scrB{position:absolute;left:0;top:1080px;width:1080px;height:840px;
  background:linear-gradient(180deg,rgba(6,9,11,0) 0%,rgba(6,9,11,.56) 32%,
    rgba(6,9,11,.80) 58%,rgba(6,9,11,.86) 100%)}
```

**스크림을 너무 올리지 않는다.** 처음에 하단을 .96 까지 올렸더니 자막 뒤 영상이 완전히 검게 죽었다.
자막에 검정 외곽선 3px 이 이미 있으므로 **.86 이면 충분하다.**

### 실사 위에서 달라지는 것

| | 도식 장면 | 실사 장면 |
|---|---|---|
| 우리가 그리는 것 | 전부 | **화면에 안 찍히는 것만** |
| 도식 위치 | 화면 전체 (y 450~1250) | **상단 (y 300~600)** · 인물이 중앙을 쓴다 |
| 밝은 곳의 텍스트 | 무대가 어두우니 문제없음 | **불투명 바닥을 깐다** |
| 효과음 | 그린 동작마다 | **지도를 다시 짠다** |

- **화면에 찍힌 사물은 그리지 않는다.** 실사에 강아지 · 법봉 · 계약서가 있으면 우리가 그린 것은 전부 뺀다.
  같은 것을 두 번 보여주면 시끄럽고, **그림이 진짜를 이길 수 없다.**
- **★ 대비 게이트가 영상 프레임을 실제로 디코드해 읽는다.** 실사 위 빨간 글씨는 거의 다 떨어진다.
  → 어두운 띠를 깔고 그 위에 얹거나, 알약 바닥을 깐 칩으로 바꾼다.
  밝은 화면에 얹히는 **리본 보조줄 · 출처 표기**도 알약 바닥이 필요하다.
- **효과음 지도를 다시 짠다.** 그린 동작이 사라지면 그 소리도 사라져야 한다.
  강아지가 뛰는 소리를 남겨 두면 화면과 어긋난다.
- 클립에 **워터마크**가 찍혀 나오는 경우가 많다. 위치는 매번 같으므로 `delogo` 한 번이면 된다.

- [ ] 길이가 **필요 프레임보다 긴가?**
- [ ] **워터마크**가 있는가? 위치는?
- [ ] 인물 · 사물이 **화면 어디를 쓰는가?** 눈금을 그려 재고 도식 자리를 정한다.

## 매번 지키는 규칙

### 기록

- **시간은 프레임(@30fps), 크기는 px.** 초는 `data-duration` 에만 쓴다.
  *초는 반올림되고 프레임은 안 된다. 실제로 렌더가 1프레임을 더 뱉은 적이 있고 프레임 검산으로 잡았다.*
- **측정값과 추정값을 섞지 않는다.** 추정에는 확신도(상/중/하)를 붙인다.
  *확신도 '하'로 적어둔 두 규칙(E27·E12)이 실제로 만들어보니 둘 다 틀렸다. 표시가 없었으면 틀린 채로 물려줬을 것이다.*
- **긴 작업은 단계 표를 먼저 보여주고 단계마다 짧게 보고한다.**
  *결과만 툭 나오면 중간에 개입할 수가 없다.*

### 컷과 모션

| 상황 | 행동 | 왜 |
|---|---|---|
| 장면을 넘길 때 | **말과 말 사이 빈 프레임에서 하드컷.** 디졸브·페이드·와이프 0 | 레퍼런스 4편 합쳐 하드컷 40/40. 말 위에서 자르면 문장이 잘린다 |
| 주석이 나타날 때 | **페이드 없이 툭 얹고 5~6프레임 정착.** 95% → 100% `power1.out` | 페이드는 주목을 못 만든다 |
| 대형 숫자가 나타날 때 | **102.4% → 100%, 6프레임.** 숫자만 수축, 나머지는 확대 | 큰 것은 다가오고 작은 것은 자라난다 |
| 숫자가 커진다고 말할 때 | 게이지·바로 보여준다. **롤링 카운트업은 쓰지 않는다** | 레퍼런스 전편 0회. 굴러가는 동안 읽을 수가 없다 |
| 자막이 바뀔 때 | **위치를 바꾸지 않는다.** 애니메이션 없음 | 자막이 움직이면 눈이 따라가느라 내용을 못 읽는다 |
| 리플·물결처럼 물리 현상 | **여기만 페이드아웃 허용** | 실제로 옅어지며 퍼지므로 페이드가 물리다 |

### 색

```
무대      중립 #14181A · 위기 #191416 · 혜택 #141A16 · 가치 #1A1814
자막      #EFE6C8 + 검정 외곽선 3px (paint-order: stroke fill)
빨강      #E12F2C   여기를 봐라 / 이만큼이다 / 이건 아니다
노랑      #EBBE2D   가치
녹색      #2FA85F   승리
고정 UI   #0CC6E4   리본 (밀도에서 세지 않는다)
캐릭터    살구 + 파랑 + 갈색 — 제3의 층. #E12F2C 를 입지 않는다
```

- **위 셋(빨강·노랑·녹색) 중 하나에 안 걸리면 색을 쓰지 않는다.**
  *색을 늘리면 각 색의 뜻이 옅어진다.*
- **캐릭터는 무대·주석과 다른 팔레트를 가진다.** *(핵심 원칙 2)*
  *같은 색이면 같은 층으로 읽힌다. 층이 갈려야 "사람이 도식 앞에 서 있다"가 된다.*
- 명암비는 무대 대비 **3:1 이상.** `check` 가 막는다.

### 화면 구성

- **고정은 안전선 둘 + 자막 기준선 하나뿐.** 나머지 1480px 는 매 장면 새로. *(핵심 원칙 1)*
  *자막이 매 장면 옮겨 다니면 내용을 못 읽는다. 반대로 자막 말고 전부 고정하면 슬라이드쇼가 된다.*
- **정보는 세계 안의 사물에 새긴다** — 간판·폰 화면·서류·달력. 오버레이 라벨은 마지막 수단.
  *밀도 상한 때문에 오버레이 라벨을 못 쓰게 되자 창구 표지와 폰 버튼으로 옮겼는데, 개수는 그대로인데 화면이 더 좋아졌다.*
- **★ 캐릭터의 동작 벡터가 정보를 겨눈다.** 캐릭터를 도식의 **대각 반대편**에 둔다. *(핵심 원칙 3)*
  *정보 옆에 캐릭터를 놓는 것만으로는 유기적이 되지 않는다. 인물을 도식 오른쪽 아래에 뒀더니 지목하는 팔이 화면 밖 허공을 가리켰다.*
- **한글 위에 반투명 요소를 겹치지 않는다.** 겹쳐야 하면 하드 스왑으로.
  *한글은 획이 많아 반투명 아래에서 뭉갠다. 탭 리플을 버튼 뒤로 보내야 라벨이 읽힌다.*
- 회전은 **주석이면 축 정렬, 세계 안의 사물이면 기울여도 된다.**
  *주석이 기울면 실수로 보이고, 사물이 반듯하면 스티커로 보인다.*

### 밀도

```
도식 장면    무대 1 + 주석 1~3 + 자막 1      (차트·목록 하나는 주석 1개로 센다)
상황극 장면  환경 2 + 캐릭터 1~2 + 소품 2    최대 6
읽어야 하는 것   어느 장면이든 최대 2개       (리본·출처 제외)
```

**비어 보이는 것을 두려워하지 않는다.** 무대가 프레임을 채우고 있다.

### 재사용 판단 — 「먼저 읽을 것」의 상세

| 층 | 무엇 | 판단 |
|---|---|---|
| **1층** | 팔레트·타이포·안전선·이징·하드컷 문법·캐릭터 생성기 | **항상 그대로.** 이게 "같은 채널로 보이는" 것의 정체다 |
| **2층** | 그래픽 자산(관공서·폰·달력·차트 틀), 구도, 효과 28종 | **아래 시험 통과 시 재사용** |
| **3층** | 장면 배치·타임라인·무게중심 | **매번 새로.** 여기를 굳히면 슬라이드쇼가 된다 |

**2층 재사용 시험 — 셋 다 통과해야 쓴다**
1. 대본 문장이 그 효과의 **발동조건에 실제로 걸리는가?** ("지난번에 예뻤으니까"는 이유가 아니다)
2. **바로 앞 장면과 형태가 다른가?**
3. 캐릭터라면 **포즈가 앞 장면과 다른가?**

> **재사용의 적은 "영상 간 반복"이 아니라 "인접 장면의 반복"이다.**
> 폰 목업은 두 편에 모두 나왔지만 문제없었다 — 둘 다 "앱으로 신청·확인"이 대본에 있었다.
> 문제는 한 영상 안에서 만세 포즈를 연달아 썼을 때 컷이 안 느껴진 것이었다.

**재사용하면 안 되는 신호**
- 대본에 없는 소품을 "화면이 비어서" 넣고 싶어질 때 → **비워 둔다**
- 지난 영상의 장면 순서를 그대로 따라가고 싶어질 때 → **대본이 다르면 장면 수도 다르다**

## 자주 틀리는 지점

### ★ `check` 통과 ≠ 화면에 나온다

다섯 게이트를 전부 통과하고도 **화면에 안 나오거나 틀리게 나온** 경우가 셋 있었다. 전부 렌더 프레임을 봐야만 잡혔다.

| 함정 | 증상 | 대응 |
|---|---|---|
| **GSAP `fromTo`** | from 에만 쓴 속성이 CSS 초깃값으로 **되돌아간다** — 리플이 나타나자마자 사라졌다 | `opacity` 를 **from·to 양쪽에** 쓴다 |
| **CSS 특정도** | `#cal .cell`(110) 이 `#d30`(100) 을 이겨 **강조 칸이 강조되지 않았다** | 예외 규칙도 같은 깊이로 — `#cal #d30` |
| **캐릭터 prefix** | 같은 prefix 로 두 포즈를 만들면 그라디언트 id 가 겹쳐 **두 번째가 첫 번째 색을 쓴다** | 포즈마다 다른 prefix. `build.py` 가 id 중복을 검사한다 |
| **`immediateRender:false` 의 초기 상태** | 트윈 시작 **전까지 CSS 초깃값 그대로 다 보인다** — 선이 그려지기도 전에 끝점·수치가 떠 있었다 | **초기 상태를 마크업에 박는다** (`r="0"` · `opacity="0"` · `stroke-dashoffset="1"`). 선만 멀쩡했던 건 dashoffset 이 마크업에 있었기 때문이다 |
| **SVG 도형 + `transformOrigin` px** | `scale` 과 함께 걸면 도형이 **화면 밖으로 밀려난다** — 빨간 끝점이 좌측 가장자리에서 발견됐다 | 도형 크기는 `attr:{r:...}` 로 키운다. `svgOrigin` 금지와 같은 계열의 함정이다 |
| **회전한 SVG `<g>`** | `transform="rotate(...)"` 를 건 그룹은 **bbox 가 커져** 컨테이너를 몇 px 넘긴다 — 인장이 `container_overflow` 로 걸렸다 | 도형을 viewBox 보다 **여유 있게** 그린다. 반지름 76 → 69 로 줄여 해결했다 |
| **한 줄 자막이 조용히 접힌다** | `.c1` 은 높이를 안 잡아서 880px 를 넘으면 **3줄이 되고도 `check` 가 통과시킨다** — 아래로 흘러 안전선을 넘는다 | 2단계에서 **13~14자**를 넘으면 무조건 `.c2` 로 나눈다. 숫자·라틴 문자가 섞이면 글자 수로는 못 재니 **렌더 프레임에서 확인한다** |

> **명암비 검사는 "적용된" 색을 잰다.** 의도한 색이 아니어도 통과한다.

```js
// ✗ 18프레임 동안 opacity 1 → 0 으로 사라진다
tl.fromTo("#ripple", { opacity: 1, scale: 0 }, { scale: 3.2, duration: f(18) });
// ✓
tl.fromTo("#ripple", { opacity: 1, scale: 0 }, { opacity: 1, scale: 3.2, duration: f(18) });
```

### 렌더가 죽거나 틀어지는 것들

| 증상 | 원인 | 해결 |
|---|---|---|
| `net::ERR_UNSAFE_PORT` 로 렌더 실패 | 내부 서버가 6669(IRC 예약)를 잡았다 | 렌더 전에 6665–6669 를 점유한다 (9단계) |
| 렌더 프레임이 통째로 검다 | 풀블리드 배경을 **루트**에 걸었다 | 자식 요소에 건다 |
| `multiple_root_compositions` | 프로젝트 루트에 `.html` 이 둘 이상 | 템플릿은 `_gen/` 안에 둔다 |
| `font_family_without_font_face` | 대체 폰트에 `@font-face` 가 없다 | 대체 폰트를 빼거나 `@font-face` 를 추가 |
| 뒤로 갈수록 나레이션이 밀린다 | 렌더가 `data-duration` 을 반올림해 1프레임을 더 뱉었다 | 장면마다 `-frames:v` 로 정확히 자른다 (10단계) |

### 레이아웃에서 반복해 나온 것들

| 증상 | 원인 | 해결 |
|---|---|---|
| 연속한 두 자막이 겹친다 | 앞 자막이 뒤 자막 시작 프레임까지 살아 있다 | **1프레임 비운다** |
| 대형 숫자가 두 줄로 접혀 자막을 침범 | 880px 를 넘겼다 | `white-space:nowrap` + 글자를 줄이거나 문구를 짧게 |
| 캐릭터 팔이 프레임 밖으로 잘린다 | 지목(point) 포즈의 팔은 박스보다 **폭의 25% 더 뻗는다** | 오른쪽 끝에 두지 않는다 |
| 만세 포즈가 상단 UI 를 덮는다 | 손이 위로 뻗는다 | 캐릭터 x 를 **리본 오른쪽 끝 +70px** 부터 |
| 팔이 정보가 아니라 허공을 가리킨다 | 캐릭터를 정보와 같은 쪽에 뒀다 | **대각 반대편**으로 옮긴다 |
| 두 색면이 갈려 보이지 않는다 | 둘 다 너무 어둡다 | 스플릿 면은 `#1E2932` / `#16291D` 까지 올린다 |
| 사물이 다른 사물 위에 떠 보인다 | z 순서는 **DOM 순서**를 따른다 (track-index 아님) | 앞/뒤를 두 클립으로 나눠 그 사이에 넣는다 |
| 리본·출처가 사라졌다 (`text_occluded`) | 전면 색면·벽이 고정 UI 를 덮었다 | **고정 UI 를 DOM 맨 뒤로.** 층 순서: 무대 → 환경 → 도식 → 캐릭터 → 고정 UI → 자막 |

### 9:16 에서만 나오는 것들

- **좌우 1:1 비교는 쓰지 않는다.** 세로에서 각 면이 540×1920 슬라이버가 된다. **상하 사선 분할**로 바꾸면 1080×640 이 되어 넉넉하다.
- **대칭 3단 적층은 캐릭터를 짓누른다.** 안전선 사이 1260px 를 인물+패널+인물이 나누면 캐릭터가 화면의 19% 가 된다. **Z자 대각**으로 풀면 29% 까지 나온다.
- **말풍선은 한 화면에 하나만.** 둘을 넣으면 반드시 도식과 겹친다.
- **디제틱 텍스트 최소 크기** — 폰 300×520, 버튼 224×86, 글자 42px. 그보다 작으면 안 읽힌다.

## 만들면서 남는 것

장면마다 `_gen/sN.html`(소스)과 `out/sN.mp4`(렌더)가 남는다. **한 장면만 고쳐 다시 렌더하고 이어 붙일 수 있다.**

두 번째 영상부터는 지난 프로젝트 폴더가 곧 예제가 된다 — 막히면 **같은 효과를 쓴 장면의 `_gen/*.html` 을 열어 본다.**
`build.py` 의 `SCENES` 딕셔너리가 그 장면의 프레임 값 전부다.

## 부록 · 클레이 캐릭터

```python
from chargen import clay_char
svg_inner = clay_char('ca', 'cheer')   # prefix, pose
```

| 포즈 | 언제 | 애니메이션 대상 |
|---|---|---|
| `rush` | 어디로 향한다 · 서두른다 | 몸통 `<g>` y 바운스 |
| `point` | 가리킨다 · 설명한다 | `#{prefix}-arm` rotation |
| `cheer` | 좋다 · 받았다 · 늘었다 | `#{prefix}-arms` rotation |
| `grief` | 곤란 · 손해 · 변수 | `#{prefix}-d1~d3` 땀방울 |

- viewBox 는 항상 `0 0 260 420`. 세로 400px 면 가로 248px.
- **prefix 는 장면 안에서 유일해야 한다.** 같으면 그라디언트 id 가 충돌한다.
- 팔 회전 원점은 **CSS** 로 잡는다 — cheer `50% 94%`, point `8% 90%`. **`svgOrigin` 은 금지** (보정 translate 가 남아 팔이 몸에서 떨어진다).
- 좌우를 뒤집으려면 GSAP 이 건드리지 않는 **안쪽 `<g>`** 에 `transform:scaleX(-1)` 를 준다.
