# Red Marker — 스타일 규칙서 v4 (최종)

> **이 문서 하나로 영상을 만들 수 있어야 한다.** 외부 대화 맥락 없이 읽고 실행할 수 있게 썼다.
> 대상 산출물: **1080×1920 (9:16 세로) / 30fps / 1362프레임 (45.4초)** HyperFrames 컴포지션.
> 시간 단위는 **프레임(30fps)**. HyperFrames의 `data-start`/`data-duration`과 GSAP은 **초**를 받으므로 `초 = 프레임 ÷ 30`으로 환산해 넣는다. (20프레임 = 0.667초)

## 0. 이 규칙서의 근거

레퍼런스 **3편**을 프레임 단위로 계측하고, 세 구간(S2·S3·S5)을 실제로 렌더해 검증했다.

| | A · 한강 수중보 | B · 머니스웨거 | C · 쿠르츠게작트 | D · 지식해적단 |
|---|---|---|---|---|
| 길이 / 규격 | 11:23 / 4K / 30fps | 11:33 / 1080p / 30fps | 12:19 / 1080p / 60fps | 17:23 / **2160×1080 (2:1)** / **24fps** |
| 진짜 하드컷 | 78 | 42 | 72 | **57** (감지 95개 중 40% 오탐) |
| 샷 길이 중앙값 | **200f** | **288f** | **212f** | **108f** (3.58초) |
| 2초 미만 샷 | 6% | 1/42 | 0개 | **29%** |
| 전환 | 하드컷 14/14 | 하드컷 14/14 | 하드컷 12/12 | 하드컷 (검증분 전부) |
| 무대 | 3D 회색 클레이 모형 | 근사블랙 + 그리드 | 장면마다 고채도 색면 | **낡은 종이 질감 + 비네팅** |
| 장면 유형 | 도식 | 도식 | 상황극 ≈ 도식 | **서사 (아카이브·지도·패러디 UI를 계속 갈아탐)** |
| 자막 | 흰색 + 검정 외곽선 | 크림, 외곽선 없음 | 없음 | 흰색 + **검정 배경 박스** |
| BGM | VO 대비 −20.5 dB | VO 대비 −21.9 dB | — | — |

### 컷 속도는 "장르"가 아니라 **장면 유형**이 정한다

A·B·C는 200~290프레임에서 만났다. D만 **108프레임**으로 절반이다. 우연이 아니라 **하는 일이 다르다.**

| 장면 유형 | 하는 일 | 샷 길이 |
|---|---|---|
| **도식·설명** | 하나의 도식이 문단 하나를 통째로 진다 | **200~290프레임** (A·B·C) |
| **서사·전개** | 사건이 연달아 일어나고 화면을 계속 갈아탄다 | **100~130프레임** (D) |

우리 대본은 제도 설명이므로 **기본은 200~290프레임**이다. 다만 **훅(첫 장면)과 마감 경고(마지막 장면)**처럼 사건이 몰아치는 구간은 D의 템포(100~130프레임)로 내려도 된다.

> **씬 감지는 그대로 믿으면 안 된다.** D는 자동 감지 95개 중 **40%가 오탐**이었다 — 지도 경로 드로잉과 카메라 팬을 컷으로 잡는다. 컷 경계 ±0.25초를 뜯어 **최대 변화량 / 인접 3프레임 평균 > 2.2배**인 것만 진짜 컷으로 센다.

### 계측 방법

| 무엇을 | 어떻게 |
|---|---|
| 컷 리듬 | ffmpeg 씬 감지 (임계 0.30), 전수 |
| 전환 성질 | 컷 경계 ±0.4초를 30fps로 뜯어 프레임간 휘도차 비교 |
| 이징 | 색 마스크의 면적·바운딩박스를 프레임별로 추적해 진행률 곡선 산출 |
| 팔레트 | 1920px 프레임에서 채도 상위 픽셀의 최빈/중앙값 |
| 자막 지오메트리 | 하단 밴드의 글자 픽셀 바운딩박스 (레퍼런스당 11~15개 시점) |
| 오디오 | RMS 엔벌로프 + 트랜지언트 고주파비·어택 분석 |
| 대본 타이밍 | whisper 전사 (110단어, 단어 단위 타임스탬프) |

## 0-1. 레퍼런스를 볼 때 조심할 것 — 세 번 반복된 착시

레퍼런스를 눈으로 기억한 내용과 프레임을 실측한 결과가 **두 편 모두에서 크게 달랐다.** 이 규칙서는 전부 실측값으로 썼다. 아래는 기억이 어긋난 방향의 목록이고, 같은 착시가 반복되므로 다음 레퍼런스를 볼 때도 참고한다.

| 기억 | 실제 |
|---|---|
| "깔끔한 2D 벡터 라인 애니메이션" (A) | **3D 렌더 무대 + 그 위의 2D 빨간 주석.** 2D로 보인 건 주석 레이어 |
| "숫자가 롤링되며 쾅 박힌다" (A·B) | **롤링 카운트업이 두 편 통틀어 0회.** 숫자는 1프레임에 완성형으로 박힌다 |
| "60조가 골드/네온으로 폭발하듯 팝업" (B) | **저채도 회색 고스트 텍스트** `#C0B8A0`. 골드도 네온도 아님 |
| "붉은 글리치와 함께 곤두박질, 화면 전체 붉은 틴트" (B) | **글리치 없음. 틴트 없음.** 빨간 숫자가 회색 숫자 위에 1프레임에 겹쳐 박힘 |
| "Scale 80% → 110% → 100%" (B) | **102.4% → 100%**, 6프레임. 훨씬 미세하다 |
| "3단으로 쿵-쿵-쿵 떨어지며" (B) | 달력 X는 **3~4프레임마다 1개씩 120프레임 연속**(기관총). 3단은 그 뒤 도트 차트이고, 행 간격은 **나레이션이 정한다**(약 126프레임) |
| "블록이 3층으로 착착 쌓이며 (390프레임)" (B) | **16프레임에 4장** (장당 4프레임). 24배 짧다 |
| "수익 80% 뱃지가 초록 불꽃 파티클과 함께" (B) | **빨간 알약 뱃지 + 흰 리더라인.** 파티클 없음, 초록 아님 |
| "내 돈 블록이 부서지듯 사라짐 (Crush)" (B) | **빨간 점선 테두리로 표시 → 그냥 제거.** 부서지는 모션 없음 |
| "MARGICAL 경고등이 1초에 2번 깜빡" (B) | 경고등 없음. **아이폰 수신전화 목업**(증권사, 빨강/초록 버튼) |
| "정중앙 수직선으로 칼같이 분할" (B) | **약 8~10도 기울어진 사선** |
| "우측은 블루 톤" (B) | **녹색** `#172D20` |
| "핵심 자막이 한 글자씩 타이핑되며 대문짝만하게" (B) | 그 대사는 **평범한 자막**으로 나온다. 타이핑 효과는 이 영상에 있긴 하지만 **다른 자리**(02:58, 문서 인용 장면)에 있다 |

**착시 세 가지** — ① 없는 화려함(글리치·파티클·네온·모핑)을 기억한다 ② 실제보다 **길다**고 기억한다(16프레임 → 390프레임) ③ 실제보다 **색이 많다**고 기억한다. 규칙서는 이 셋을 전부 반대로 잡았다.

## 0-2. 이 규칙서를 쓰는 법 — 레퍼런스에서 뽑는 것 / 대본에 적용하는 것

이 문서는 **특정 영상을 베끼는 문서가 아니다.** 어떤 대본과 음원이 들어와도 같은 질감으로 뽑아내기 위한 **범용 모션 문법**이다. 그래서 두 가지를 엄격히 분리한다.

| | 레퍼런스에서 **뽑는 것** | 대본에 **적용하는 것** |
|---|---|---|
| 정체 | 모션 문법 — 컷 리듬, 팔레트, 이징 곡선, 전환 방식, 밀도 | 그 문법을 이번 소재에 대입한 결과 |
| 근거 | **프레임 실측** | 대본의 의미 단위 |
| 바뀌는가 | 안 바뀐다. 부동산이든 금융이든 동일 | 대본마다 매번 다시 짠다 |
| 예 | "큰 숫자는 1프레임에 102.4%로 박히고 6프레임에 100%로 수축한다" | "그러니 그 숫자를 말하기 시작하는 프레임에서 그렇게 한다" |

**레퍼런스에 없는 것을 규칙에 넣지 않는다.** 실측이 아닌 항목은 **[요청 기반]**으로 표시하고 근거를 함께 적는다 — 나중에 이 문서만 보고 작업할 때 "이건 어디서 나온 값이지"를 되물을 수 있어야 한다.

> **레퍼런스를 볼 때 흔히 생기는 착각** — "그 영상 몇 분쯤에 이런 게 있었다"고 기억한 것이, 실제로 그 시각을 열어보면 전혀 다른 화면인 경우가 많다. 기억한 것은 대개 **"내 소재라면 이렇게 쓰겠다"는 적용 아이디어**이지 레퍼런스의 관찰이 아니다. 둘은 섞이면 안 된다.
>
> 이 문서에는 **프레임을 열어 실제로 확인한 것**만 규칙으로 들어간다. 적용 아이디어는 아이디어 칸에 따로 적는다.

## 0-3. 새 대본·음원이 들어왔을 때의 절차

**입력**: 나레이션 음원(mp3/wav) 1개 + 대본 텍스트 1개. 그 외 재료는 필요 없다.

| 단계 | 할 일 | 산출 |
|---|---|---|
| 1 | `npx hyperframes transcribe <음원> --language ko` | 단어 단위 타임스탬프 |
| 2 | 대본을 **단어 경계**에 맞춰 한 줄씩 끊는다. 기준은 글자 수가 아니라 **호흡** | 자막 표 (시작f / 끝f / 길이f) |
| 3 | 자막 줄을 **의미 단위로 묶어** 장면을 만든다. 목표는 **장면당 160~290프레임**, 컷은 **말과 말 사이 빈 프레임**에 | 장면 표 |
| 4 | 각 장면에 **무대 형태**를 고른다 — 실물이면 바닥면+물체, 추상이면 빈 그리드 | 장면별 무대 |
| 5 | 각 장면에 **장면 틴트**를 고른다 — 위기/혜택/가치/중립 | 배경 색상 |
| 6 | 자막의 **동사·수치**를 보고 3장 효과 목록의 **발동조건**에 맞는 효과를 고른다. 장면당 **최대 3개** | 효과 배치 |
| 7 | 효과를 **그 단어를 말하기 시작하는 프레임**에 물린다 | 타임라인 |
| 8 | `npx hyperframes check` → `snapshot` → `render` | MP4 |

**6단계가 이 규칙서의 핵심이다.** 효과를 고르는 기준은 "예뻐 보여서"가 아니라 **말이 어떤 상태인가**다. 3장의 각 효과에 붙은 "발동조건" 칸이 그 판단표다.

| 말이 이런 상태면 | 이 효과 |
|---|---|
| 무언가에 이름을 붙인다 | E3 라벨 플레이트 |
| 조건·기간·분류를 한 단어로 못 박는다 | E4 칩 라벨 |
| 수치가 커진다 · 한도가 늘어난다 | E5 게이지 채움 |
| 숫자를 소리내어 말한다 | E6 대형 숫자 슬램 |
| "A였는데 B가 됐다" | E7 고스트 교체 |
| 여러 개가 합쳐져 총량이 된다 | E8 블록 스택 |
| 하나가 없어진다 · 못 쓰게 된다 | E9 블록 소멸 |
| 시간이 줄어든다 · 기한이 다가온다 | E10 스탬프 스태거 |
| 같은 축에서 둘 이상을 비교한다 | E11 도트-라인 차트 |
| 둘 중 하나만 · 둘이 갈린다 | E12 대비 스플릿 |
| "안 된다 · 못 한다 · 없어진다" | E13 X 마크 |
| 장소·시점을 콕 집는다 | E14 핀 드롭 |
| 작은 부분을 조용히 가리킨다 | E15 리더라인 |
| 사람의 감정·행동을 가리킨다 | E17 클레이 캐릭터 |
| 수량을 세어 보여준다 | E18 픽토그램 격자 |
| 장면의 주제를 못 박는다 | E19 리본 태그 |
| 수치의 출처를 밝힌다 | E20 출처 표기 |
| 손으로 조작한다 · 신청한다 | E23 스마트폰 탭 |

**이 표에 걸리는 말이 없으면 그 장면에는 효과를 넣지 않는다.** 무대와 자막만으로 간다. 비어 보이는 것을 두려워하지 않는다.

## 1. 출력 1 — 스타일 시트 (본체)

### 1.1 제1원칙 — 두 레퍼런스가 독립적으로 합의한 것

> **설명은 컷이 아니라 주석으로 진행된다.**

설명형 세 편(A·B·C)의 컷이 아주 느리다(중앙값 **200 / 288 / 212프레임**). 2초 미만 샷은 A가 6%, B는 42개 중 1개, **C는 0개**다. 서사형 D만 108프레임으로 절반인데, 그건 **하는 일이 달라서**지 원칙이 틀려서가 아니다. 그런데도 지루하지 않은 이유는, **한 샷 안에서 도식과 주석이 순서대로 들어오며 설명을 진행**하기 때문이다.

화면이 심심하면 **컷을 늘리지 말고 주석을 하나 더 얹는다.** 이 원칙에서 나머지가 전부 파생된다.

### 1.2 2층 구조

| 층 | 정체 | 색 | 역할 |
|---|---|---|---|
| **무대(Stage)** | 프레임을 100% 채우는 어두운 무채색 공간 + 희미한 그리드 | 무채색 전용 | 아무것도 설명하지 않는다. 정보가 **빠진** 상태로 먼저 나온다 |
| **주석·도식(Marker)** | 무대 위에 얹힌 평면 도형·숫자·블록·차트 | 빨강 1개 + 흰색 (+ 의미색 2개) | 전부 설명한다 |
| **자막(Caption)** | 화면 하단 고정 | 크림 + 검정 외곽선 | 말을 받아쓴다. 절대 움직이지 않는다 |

**무대의 두 가지 형태 — 내용에 따라 고른다.**

| 형태 | 언제 | 구성 |
|---|---|---|
| **빈 그리드** (기본, 레퍼런스 B) | 추상 도식을 놓을 때 — 블록·게이지·차트·숫자 | 근사블랙 + 그리드만. 도식은 공중에 뜬다 |
| **바닥면 + 물체** (레퍼런스 A) | 실물을 보여줄 때 — 통장·서류·카드 | 근사블랙 + 수평선 + 살짝 밝은 바닥면. 물체가 그 위에 선다 |

**둘을 한 장면에 섞지 않는다.** 추상 도식에 바닥면을 깔면 무겁고, 실물을 공중에 띄우면 붕 뜬다.

**장면 틴트 — 레퍼런스 C에서 가져온 세 번째 축.** C는 장면마다 배경 전체를 다른 고채도 색으로 바꾼다(민트 `#B0F8F0` 출산율 / 다크그린 `#006050` 세대 / 퍼플 `#381068` 중국 / 크림옐로 `#F8F0A8`). **배경이 그 장면의 주제를 색으로 진다.**

우리는 어두운 무대를 유지해야 하므로(명암비) 이걸 그대로 못 쓴다. 대신 **아주 옅은 틴트**만 가져온다.

| 장면 성격 | 무대 바탕 | 색상 이동 |
|---|---|---|
| 중립 · 설명 | `#14181A` | 기본 |
| 위기 · 손해 · 마감 | `#191416` | 빨강 쪽으로 |
| 혜택 · 증가 · 성공 | `#141A16` | 녹색 쪽으로 |
| 가치 · 자산 | `#1A1814` | 노랑 쪽으로 |

**명도는 그대로 두고 색상만 옮긴다.** 눈에 띄게 하면 안 된다 — 봤을 때 "색이 바뀌었네"가 아니라 "분위기가 다르네"여야 한다. 네 값 모두 `#E12F2C` 대비 3:1을 넘는다.

**색을 몇 개 쓰는가 — 무채색 무대 + 빨강 1개 + 의미색 2개.**

- **빨강 `#E12F2C`가 주 강조다.** 화면당 빨강이 없는 장면은 있어도, 빨강 아닌 강조색만 있는 장면은 없다.
- **노랑 `#EBBE2D`과 녹색 `#2FA85F`은 뜻이 있을 때만.** 노랑 = 가치·자산·논리. 녹색 = 승·현금·안전. 장식으로 쓰면 즉시 스타일이 무너진다.
- 두 레퍼런스 모두 **파랑을 강조로 쓰지 않는다.** (A의 청록은 "물"이라는 뜻일 때만)

**명암비 (전부 `#14181A` 바탕 기준, WCAG AA 3:1 필요)**

| 색 | 명암비 | |
|---|---|---|
| `#EFE6C8` 자막 | **14.3 : 1** | ✓ |
| `#EBBE2D` 노랑 | **10.1 : 1** | ✓ |
| `#2FA85F` 녹색 | **5.9 : 1** | ✓ |
| `#E12F2C` 빨강 | **4.0 : 1** | ✓ |

> **빨강은 여유가 가장 적다.** 바탕을 `#14181A`보다 밝히면 즉시 미달한다. 실측: `#33393B` 위 2.12:1 실패, 밝은 클레이 `#C9CDCD` 위 2.81:1 실패 — **레퍼런스 A조차 밝은 무대에서는 통과하지 못한다.** 광원 풀(흰색 3.5%)·그레인(5%)도 바탕을 들어올리므로 이 값들을 함께 지킨다. **빨강을 밝게 바꿔 해결하지 않는다.**

### 1.6 움직임의 성질 (전부 실측)

| 항목 | 실측값 | 출처 | 확신도 |
|---|---|---|---|
| **주석 등장** | **페이드 없음. 1프레임 팝.** | A·B | 상 |
| 팝 직후 정착 — 보조 요소 | **95% → 100%**, 5프레임, `power1.out` | A | 상 |
| 팝 직후 정착 — **대형 숫자** | **102.4% → 100%**, 6프레임 (더 세게 박힘) | B | 상 |
| 게이지·바 채움 (이산 수치) | **20프레임 `power2.out`** — 진행률 t=.2→41% / .5→77% / .8→96% | A | 상 |
| 스케일 은유 성장 (연속) | **150프레임 `power2.out`** — 진행률 t=.2→41% / .4→67% / .6→86% | B | 상 |
| 블록 스택 쌓기 | **16프레임에 4장** (장당 4프레임), 아래→위 | B | 상 |
| 스탬프 스태거 (달력 X) | **3~4프레임마다 1개**, 120프레임 연속 | B | 상 |
| 픽토그램 격자 채우기 | **일정 속도(선형)**, 100칸이 **42프레임**에 완성 — 프레임당 2~3칸 | C | 상 |
| 오브젝트 미세 아이들 | 완성 후 면적 **±1%** 흔들림 | C | 중 |
| 도트-라인 행 그리기 | **24~30프레임**, 강한 감속(`power3.out`급) | B | 중 |
| 도트-라인 행 **간격** | **나레이션이 정한다** (실측 126프레임) | B | 상 |
| 핀 드롭 | **18프레임 2단** — 8f 진입(최종보다 20px 위 오버슛) + 10f 낙하 | A | 상 |
| X 마크 | **33프레임 3단** — 10f 확장 / 10f 잉크 채움 / 8f 9% 수축 | A | 중 |
| **장면 전환** | **하드컷 100%.** A 14/14, B 14/14 | A·B | 상 |
| 배경 움직임 | **없음** (B). A의 카메라 푸시는 3D 무대 전용 | B | 상 |

> **아이들 모션은 기본 금지, C만 예외.** A·B는 완성 후 완전히 정지한다. C만 오브젝트가 ±1% 미세하게 흔들린다. 우리 기본값은 **정지**다 — 세로 쇼츠에서 흔들림은 산만하고, 하우스 룰(motion-doctrine)도 "motion must PERFORM, not breathe"로 금지한다. 긴 홀드(200프레임 이상)가 죽어 보일 때만 **캐릭터와 픽토그램 격자에 한해** scale ±1.5% / 주기 50프레임까지 허용한다.

**두 이징만 기억하면 된다.**
- **`power2.out`** — 무언가가 커지거나 채워질 때. 길이만 다르다: 이산 수치 20프레임, 연속 성장 150프레임.
- **`power1.out` 5~6프레임** — 팝 직후 정착. 방향만 다르다: 보조는 95%→100%(확대), 대형 숫자는 102.4%→100%(수축).

**툭 튀며 도착하나, 스르륵 미끄러지나, 딱 끊기나?**
→ **딱 끊긴 뒤 잠깐 정착한다.** 페이드 인은 두 편 통틀어 0회. **이 5~6프레임 정착이 있고 없고가 이 스타일의 전부다.**

**겹쳐 들어오나, 차례로 들어오나?**
→ **차례로.** 동시 등장 0회. A 실측 간격 20 / 38프레임. B는 나레이션이 간격을 정한다(126프레임까지). **최소 12프레임, 그 이상은 말이 정한다.**

### 1.7 밀도

**무대 1 + 주석 1~3 + 자막 1.** 최빈값은 주석 2개.

레퍼런스 B는 극단적으로 비어 있다 — 근사블랙 화면에 도식 하나와 라벨 하나가 전부인 장면이 많다. **9:16에서는 B 쪽에 맞춘다.** 화면이 비어 보이는 것을 두려워하지 않는다. 무대가 프레임을 채우고 있으므로 비어 보이지 않는다.

### 1.9 스타일 이름

**가장 가까운 것: Swiss Pulse.** 그리드 정렬 구도, 숫자가 프레임을 지배, 하드컷, 장식 전환 없음, `energy: high`, 진입 이징이 power 계열.

**변형 3가지:**
1. **accent `#0066FF` → `#E12F2C`.** 유일하게 중요한 색 변경.
2. **평면 배경 → 어두운 무대 레이어.** 그리드는 배경이 아니라 무대의 바닥이다. 실물을 다룰 때만 수평선 + 바닥면을 추가한다.
3. `atmosphere: [grid-lines, registration-marks]` 유지, 불투명도 4.5%.

Shadow Cut에서 한 줄만 빌린다 — *"elements emerge from darkness — reveal is the narrative."* 단 느린 진입(`entrance: 0.8`)은 버리고 **0프레임 팝**을 쓴다.

```yaml
name: Red Marker
colors:
  primary: "#14181A"
  on-primary: "#EFE6C8"
  accent: "#E12F2C"
  value: "#EBBE2D"      # 의미 한정
  win: "#2FA85F"        # 의미 한정
  floor: "#1B2022"
  object: "#6D7678"
typography:
  stat:     { fontFamily: Pretendard, fontSize: 220px, fontWeight: 900, letterSpacing: -0.03em }
  headline: { fontFamily: Pretendard, fontSize: 112px, fontWeight: 800, letterSpacing: -0.02em }
  caption:  { fontFamily: Pretendard, fontSize: 64px,  fontWeight: 700, letterSpacing: -0.01em }
  chip:     { fontFamily: Pretendard, fontSize: 38px,  fontWeight: 700 }
  label:    { fontFamily: Pretendard, fontSize: 34px,  fontWeight: 500 }
rounded: { none: 0px, plate: 8px, chip: 10px, pill: 9999px }
motion:
  energy: high
  easing:
    entry:        "none"        # 0프레임 팝. 페이드 금지
    settle:       "power1.out"  # 보조 5f (95→100%) / 대형 숫자 6f (102.4→100%)
    fill:         "power2.out"  # 이산 20f / 연속 150f
    draw:         "power3.out"  # 차트 행 그리기 24~30f
    exit:         "none"
  duration: { pop: 0, settle: 0.17, fill: 0.667, grow: 5.0, stack: 0.533 }
```

## 1-A. 상황극 문법 — 정보가 이야기 안에 살게 한다

### 왜 필요한가

A와 B는 **도식 위주**다. 화면에 사람이 거의 없다. C는 다르다 — 프레임의 절반이 **상황극**이다(놀이터에서 구슬치기 하는 노인들, 병실에 링거 꽂고 앉은 캐릭터, 연설장에서 말문이 막힌 사람, 공원에서 피크닉하는 무리). 나머지 절반이 픽토그램 격자·지도·인구 피라미드 같은 도식이고, **둘을 번갈아 친다.**

도식만 이어지면 정보는 전달되지만 **감정이 안 붙는다.** 상황극만 이어지면 재밌지만 **숫자가 안 남는다.** 그래서 둘을 겹치되, **틀로 나누지 않고 서로 스며들게 한다** — 숫자가 간판에 적히고, 캐릭터가 그 숫자를 들어올린다.

### 안전 영역만 고정하고, 나머지는 매 장면 새로 짠다

**틀을 고정하면 7장면이 전부 같아 보인다.** 지켜야 할 선은 두 개뿐이다.

| 선 | 값 | 이유 |
|---|---|---|
| 상단 안전선 | **y ≥ 120** | 이 위는 잘릴 수 있다 |
| 하단 안전선 | **y ≤ 1600** | 쇼츠 플랫폼 UI가 덮는다 |
| 자막 | **하단 기준선 y = 1560 고정** | 자막만은 절대 안 움직인다. 매 장면 자리가 바뀌면 눈이 따라가느라 내용을 못 읽는다 |

**그 사이 1480px는 매 장면 자유롭게 다시 구성한다.** 대형 숫자가 반드시 위에 있을 필요도, 캐릭터가 반드시 가운데 있을 필요도 없다.

### 텍스트를 놓는 네 가지 방식

레퍼런스 C는 글자를 **화면 위에 얹기만 하지 않는다.** 말풍선, 병원 벽의 십자 표시, 노트북 화면, 피자 상자 라벨처럼 **세계 안의 사물에 새겨** 놓는다.

| 방식 | 무엇 | 언제 |
|---|---|---|
| **① 자막** | 하단 고정, 흰 크림 + 검정 외곽선 | 항상. 유일하게 자리가 고정된 텍스트 |
| **② 디제틱 (세계 안 글자)** | 간판 · 폰 화면 UI · 표지판 · 서류 · 달력 · 말풍선에 **새겨진** 글자. 그 사물의 기울기·원근을 그대로 따른다 | 그 정보가 **실제로 어딘가에 적혀 있을 법할 때** — 마감일, 앱 버튼, 창구 번호 |
| **③ 오버레이** | 화면 위에 얹힌 대형 숫자 · 라벨 플레이트 · 리본 태그. 축 정렬 | 그 수치가 **세상에 적혀 있을 물건이 없을 때** — 비율 · 배수 · 추상적인 총액 |
| **④ 캐릭터가 다루는 텍스트** | 글자가 **물리 객체**가 된다. 들어올리거나, 올라타거나, 도장으로 찍는다 | 그 수치가 **이 사람에게 일어난 일일 때** |

**한 장면에 ②③④ 중 최대 두 가지.** 셋을 다 쓰면 어디를 봐야 할지 모른다. ①은 언제나 별도로 센다.

> **디제틱을 우선한다.** 같은 정보를 간판에 새길 수 있으면 오버레이로 띄우지 않는다. 마감일은 유리문에 붙은 안내문이 되고, 신청 버튼은 폰 화면 속 UI 가 된다. 그래야 정보가 이야기 안에 산다.

### 캐릭터 × 텍스트 인터랙션 3종

| 동작 | 모션 | 언제 |
|---|---|---|
| **들어올린다** | 캐릭터가 팔을 뻗은 뒤(9f `back.out`), 숫자가 손끝에 붙어 함께 `y −80px`(14f `power2.out`). 숫자에 캐릭터의 접지 그림자가 같이 이동 | 혜택·수치가 커질 때 |
| **올라탄다** | 바 차트가 솟을 때(20f `power2.out`) 캐릭터가 바 끝에 붙어 같이 올라간다. 도착 시 `bounce.out` 8f | 증가폭이 메시지일 때 |
| **찍는다 · 누른다** | 도장·손가락이 `y −120 → 0`(8f `power2.in`) 후 접촉 프레임에 **대상이 `scale 1.06 → 1`**(6f) + 원형 리플 | 확정·승인·신청할 때 |

**인터랙션은 장면당 1회.** 두 번 쓰면 약해진다.

### 구도 — 연속 두 장면이 같은 구도를 쓰지 않는다

레퍼런스 C의 스캔 25장이 **전부 다른 구도**였다. 정면 와이드, 부감, 앙각, 아이소메트릭, 좌우 스플릿, 근경 클로즈업, 극단 원근이 섞여 있다.

| 구도 | 쓰는 법 | 어울리는 상황 |
|---|---|---|
| **정면 와이드** | 지평선 중앙, 캐릭터 전신 | 상황을 소개할 때 |
| **근경 클로즈업** | 캐릭터 상반신이 화면의 60% 이상, 배경은 흐린 색면 | 감정이 메시지일 때 |
| **대각 스플릿** | 6~10° 사선으로 화면 분할 | 둘이 갈릴 때 |
| **좌우 1:1** | 수직 분할, 양쪽에 캐릭터 1명씩 | 두 방법을 나란히 비교할 때 |
| **원근 줌인** | 소실점을 향해 오브젝트가 커지며 배열 | 하나가 압도적으로 커질 때 |
| **부감 (위에서)** | 바닥면을 넓게, 오브젝트를 위에서 | 전체 구조를 보여줄 때 |
| **앙각 (아래서)** | 지평선을 화면 하단 1/4에, 대상을 크게 | 벅차거나 압도될 때 |
| **아이소메트릭** | 30° 축, 받침대 위에 오브젝트 | 수치를 물리적 높이로 보여줄 때 |
| **액자 지도** | 지도를 프레임 안에 넣고 **카메라가 그 위를 팬·줌**. 좌우에 인물이 서서 반응 | 동선·위치·이동을 보여줄 때 |
| **원근 통과** | 벽에 뚫린 문 → 문이 열리고 **벽이 카메라를 지나쳐 물러난다** (E28) | 막혀 있던 것이 열릴 때 |

**연속 금지가 유일한 규칙이다.** 나머지는 상황이 정한다. 7장면이면 최소 5종을 쓰게 된다.

### 화면의 무게중심도 매 장면 옮긴다

house-style이 "everything centered with equal weight"를 lazy default로 지목한다. 매 장면 **무게중심을 다른 사분면**에 둔다 — 좌상 / 우상 / 좌하 / 우하 / 중앙. 자막만 중앙 고정이므로, 그 위 1480px 안에서 균형을 깨는 것이 오히려 안전하다.

### 대본 문장 → 상황 변환 판단표

**문장의 동사와 상태**를 보고 상황을 고른다. 명사가 아니라 **동사**를 본다.

| 문장이 이런 뜻이면 | 환경 | 캐릭터 행동 | 소품 |
|---|---|---|---|
| 기한이 임박했다 | 벽시계 걸린 실내 / 은행 앞 | 시계를 보며 뛴다 | 시계, 서류봉투 |
| 손해를 본다 · 놓친다 | 텅 빈 어두운 방 | 머리를 감싸쥔다 (포즈 ①) | 땀방울, 떨어진 서류 |
| 선택지가 좁다 · 하나만 된다 | 좁은 복도, 문 하나 | 문 앞에서 멈춰 선다 | 잠긴 문, 자물쇠 |
| 선택지가 넓어진다 | 문 너머로 펼쳐진 단지 | 문을 연다 | 열린 문, 아파트 실루엣 |
| 혜택이 늘어난다 | 밝은 무대 | 두 팔 번쩍 (포즈 ②) | 상승 화살표 |
| 그대로 유지된다 | 그대로 | 팔짱 끼고 끄덕인다 | 도장, 체크 |
| 창구를 방문한다 | 은행 카운터 | 번호표를 뽑고 기다린다 | 번호표, 대기 번호판 |
| 앱으로 신청한다 | 침대 · 소파 | 누워서 폰을 탭한다 | 스마트폰, 커피잔 |
| 설명한다 · 가리킨다 | 빈 그리드 (도식 장면) | 포인터 펜으로 가리킨다 (포즈 ③) | 펜 |

**표에 없는 문장은 상황극을 만들지 않는다.** 억지로 만든 상황은 도식보다 나쁘다 — 그때는 도식 장면으로 간다.

### 배치 규칙 4개

1. **상황극과 도식을 번갈아 친다.** C 실측 비율이 약 1:1이다. **연속 3장면 이상 도식만 가지 않는다.**
2. **상황극 장면에도 정보 밴드는 살아 있다.** 이야기만 있고 숫자가 없으면 정보 영상이 아니다.
3. **한 장면에 한 동작.** 뛰면서 시계 보고 땀 흘리고 문 여는 건 4개 장면이지 1개가 아니다.
4. **캐릭터 2명은 대비일 때만** — 과거/현재, 창구/앱처럼 좌우(또는 상하)로 갈릴 때. 그 외에는 1명.

### 상황극 장면의 밀도

**환경 2 + 캐릭터 1~2 + 소품 2 = 6개까지.** 도식 장면의 상한(주석 3개)과 다르다 — 환경 요소는 배경이지 주석이 아니기 때문이다. 다만 **읽어야 하는 것**(오버레이 텍스트·디제틱 텍스트·라벨)은 상황극에서도 **최대 2개**다. 리본 태그와 출처 표기는 화면 가장자리 고정 UI라 세지 않는다.

### 2.4 주석·도식 레이어

- 한 화면에 **최대 3개**, 최빈 2개.
- 등장은 **팝**: 0프레임에 나타나 5~6프레임 동안 100%로 정착.
  - 보조 요소(라벨·칩·게이지·리더라인): **95% → 100%**, 5프레임
  - 대형 숫자: **102.4% → 100%**, 6프레임
- **페이드 인/아웃 절대 금지.** 사라질 때도 즉시 사라진다(clip 경계).
- 2개 이상일 때는 **차례로**, 간격 **최소 12프레임**. 그 이상은 나레이션이 정한다 — 다음 주석은 **그것을 설명하는 말이 시작될 때** 나온다.

**캐릭터의 자리** — 캐릭터는 무대도 주석도 아닌 **제3의 레이어**다. 레퍼런스 B가 풀컬러 인물 컷아웃을 쓰는 것과 같은 자리다.
- **자기 팔레트를 갖는다**(피부·머리·옷). 이 색들은 **캐릭터 안에서만** 쓰고 도식·주석에는 쓰지 않는다.

**규칙 4개**
1. **캐릭터는 빨강 `#E12F2C`를 입지 않는다.** 강조색의 뜻을 훔친다.
2. 클레이 팔레트는 **캐릭터 안에서만.** 도식·주석에 쓰지 않는다.
3. 밀도 계산에서 **주석 1개**로 센다. 땀방울·화살표·펜은 딸린 것으로 보고 따로 세지 않는다.
4. 한 장면에 **1명**.

> **⚠ 구현 함정 4가지**
> - **SVG 회전축은 도형으로 잡는다.** `transform-box:fill-box` + 퍼센트 원점은 그룹 **바운딩박스** 기준이라, 시계 바늘처럼 한쪽으로만 뻗은 도형은 원점이 어긋난다. 회전 중심을 감싸는 **투명 원**(`fill="none"`)을 그룹에 하나 넣어 bbox를 대칭으로 만들고 `50% 50%`를 쓴다.
> - **팔 회전은 CSS로.** GSAP `svgOrigin`은 그룹에 보정 이동을 남겨 팔이 통째로 밀린다. `transform-box:fill-box; transform-origin:<x>% <y>%` 를 CSS에 주고 GSAP은 `rotation`만 건다. ②는 `50% 94%`, ③은 `8% 90%`.
> - **`rotateY` 틸트는 안쪽 래퍼 div에.** clip 요소에 CSS transform을 주면 GSAP tween과 충돌해 lint가 막는다. `<div class="clip"><div class="tilt"><svg>…` 구조로 나눈다.
> - **그라디언트·필터 id에 접두사를 붙인다.** HyperFrames는 조립된 페이지 전체에서 id가 유일해야 한다. 캐릭터가 여럿이면 `c1-skin`, `c2-skin`처럼 분리한다.

**해방감의 정체는 "벽이 사라지는 것"이 아니라 "벽이 나를 지나쳐 가는 것"이다.** 처음엔 벽 클립을 1프레임에 끝냈는데, 그러면 세계가 커지기도 전에 전부 보여서 **확장을 스포일한다.** 벽을 밀어내야 카메라가 문을 통과한 것으로 읽힌다.

**평행이동이 아니라 화면 중심 기준 확대여야 한다.** 벽 조각을 각각 x/y로 밀면 문틀(확대)과 따로 논다. 조각마다 `transform-origin`을 **화면 중심이 원점에 오도록** 퍼센트로 계산해 두고 **전부 같은 배율**로 확대하면 하나의 구조물이 통째로 물러난다.

```
origin% = (화면중심 − 요소시작) / 요소크기 × 100
```

| 조각 | 위치·크기 | transform-origin |
|---|---|---|
| 상단 벽 | (0, 0, 1080, 440) | `50% 184.09%` |
| 하단 벽 | (0, 1180, 1080, 740) | `50% -50%` |
| 좌측 벽 | (0, 440, 280, 740) | `192.86% 50%` |
| 우측 벽 | (800, 440, 280, 740) | `-92.86% 50%` |
| 문틀 | (262, 422, 556, 776) | `50% 50%` |

**배율은 근경과 원경이 달라야 한다.** 벽 **3.4×** 대 세계 **1.67×**. 같은 값이면 시차가 없어 평면으로 보인다.

**문 너머 세계는 화면 전체 크기(1080 × 1500)로 만든다.** 문 크기로 만들면 벽이 물러날 때 생기는 틈으로 **무대 격자가 비친다.** 확대 목표는 1.00이 아니라 **1.02** — 1.00이면 마지막 몇 프레임에 화면 양 끝 16px이 빈다.

**문은 `transformPerspective`를 from·to 양쪽에 쓴다.** 부모에 `perspective`를 걸지 않아도 요소 자체에서 처리된다. 열린 뒤에는 104도 회전이라 옆면 슬리버가 되므로 **클립을 그냥 끝내도 사라지는 것이 안 보인다.**

`clay_char(prefix, pose)` 의 **prefix 를 반드시 다르게 준다.** 같은 prefix 로 두 포즈를 만들면 그라디언트·필터 id 가 그대로 겹쳐 두 번째 캐릭터가 첫 번째의 색을 쓴다. `check` 는 이걸 잡지 못한다. 생성 후 아래로 확인한다.

```python
ids = re.findall(r'\sid="([^"]+)"', html)
dup = [k for k, v in collections.Counter(ids).items() if v > 1]
assert not dup, dup
```

```css
#cal .cell { background:#141A1D }   /* id 1 + class 1 = 110 */
```

### ★ GSAP `fromTo` 함정 — from에만 쓴 속성은 되돌아간다

```js
// ✗ 리플이 18프레임 동안 opacity 1 → 0 으로 사라진다
tl.fromTo("#ripple", { opacity: 1, scale: 0 }, { scale: 3.2, duration: f(18) });

// ✓ 양쪽에 다 쓴다
tl.fromTo("#ripple", { opacity: 1, scale: 0 }, { opacity: 1, scale: 3.2, duration: f(18) });
```

`fromTo`의 **from에만 있고 to에 없는 속성은 CSS 초깃값으로 되돌아간다.** CSS에 `opacity:0`을 걸어둔 요소는 특히 위험하다 — 나타나야 할 것이 나타나자마자 사라지는데, `check`의 다섯 게이트가 전부 통과하므로 **렌더 프레임을 직접 봐야만 잡힌다.**

**탭 리플은 버튼 뒤에 둔다.** DOM에서 버튼보다 앞에 두면 반투명 원이 한글 버튼 라벨을 덮어 읽을 수 없게 된다.

### 장면을 이어 붙이는 방법

장면마다 무대 색·id·자막 타이밍이 달라 한 파일로 합치면 id가 충돌한다. **장면별로 렌더한 뒤 이어 붙이고 나레이션을 통으로 얹는다.**

```bash
# ① 장면마다 정확한 프레임 수로 자른다 (렌더가 1프레임 더 나오는 일이 있다)
ffmpeg -i s2.mp4 -an -frames:v 143 -c:v libx264 -crf 17 -preset medium -pix_fmt yuv420p -r 30 p2.mp4
# ② concat 디먹서로 잇는다
ffmpeg -f concat -safe 0 -i list.txt -i 나레이션.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest out.mp4
```

**장면 경계 프레임 수를 반드시 검산한다.** `hyperframes render` 는 `data-duration` 을 반올림해 **1프레임을 더 뱉는 경우가 있다.** 7장면 중 2장면이 그랬고, 그대로 이으면 뒤로 갈수록 나레이션이 밀린다.

```bash
ffprobe -v error -select_streams v -count_frames -show_entries stream=nb_read_frames -of csv=p=0 out.mp4
```

## 5. 소리와 화면이 만나는 지점

| 항목 | 레퍼런스 A | 레퍼런스 B |
|---|---|---|
| BGM 유무 | 있음 (공백 잔여 −40.8 dB) | 있음 (공백 잔여 −48.7 dB) |
| BGM 레벨 | **VO 대비 −20.5 dB** | **VO 대비 −21.9 dB** |
| 컷 효과음 | 없음 (+1.0 dB) | **없음** (트랜지언트 4/4 발화로 판정) |

**규칙 4개**

1. **컷은 말과 말 사이의 빈 프레임에.** 2.5절 표의 경계가 그 지점이다. 말 위에서 자르지 않는다.
2. **주석 팝은 그 단어를 말하기 시작하는 프레임에.** 3장의 "주요 단어의 정확한 프레임" 표를 쓴다.
3. **성장 애니메이션은 그 수치를 말하는 길이 안에 끝나야 한다.** 그 단어가 f790–815(25프레임)에 걸쳐 있으면 채움은 f792–812에 넣는다.
4. **BGM은 VO보다 −21 dB.** 두 레퍼런스의 평균값. **효과음은 넣지 않는다** — 두 편 모두 컷에 효과음이 없다.

**주석 간격의 진짜 규칙 (B에서 배운 것)** — 주석 사이 간격은 고정값이 아니라 **나레이션**이다. A는 20~38프레임, B는 126프레임까지 벌어졌다. 다음 주석은 그것을 **설명하는 말이 시작될 때** 나온다. 최소 12프레임만 지키고 나머지는 말에 맡긴다.
